# Backyard Airport — เดโมระบบจองที่จอดรถ

ลูกค้าจองที่จอดและรถรับส่งสุวรรณภูมิใน LINE จ่ายผ่าน PromptPay ระบบตรวจสลิปให้เอง แอดมินกับคนขับดูงานผ่านเว็บ

| หน้า | ใช้โดย | ทำอะไร |
| --- | --- | --- |
| `/liff/book` | ลูกค้า (เปิดจากเมนู LINE) | เลือกวัน ใส่ทะเบียน เลือกรถรับส่ง เห็นที่ว่างและราคาทันที |
| `/liff/pay/[id]` | ลูกค้า | QR PromptPay ตามยอด นับเวลากันที่ 15 นาที ส่งสลิป |
| `/liff/my` | ลูกค้า | การจองของฉัน |
| `/admin` | แอดมิน (รหัสผ่าน) | ที่ว่าง 30 วัน เที่ยวรถ 3 วัน คิวทะเบียนไม้กั้น สลิปที่ตรวจไม่ผ่าน |
| `/driver` | คนขับ (ล็อกอิน) | งานของรถตัวเองวันนี้/พรุ่งนี้ กดเปลี่ยนสถานะ แจ้งปัญหา ส่งข้อความหาลูกค้าอัตโนมัติ |
| `/api/line/webhook` | LINE | ต้อนรับเพื่อนใหม่ ตอบราคา ตอบเรื่องแอดมิน (ใช้ข้อความตอบกลับ ไม่เสียโควตา) |

## ติดตั้ง (ราว 30 นาที)

### 1. Supabase
1. สร้างโปรเจกต์ใหม่ (region Singapore)
2. SQL Editor: รัน `supabase/migrations/0001_init.sql` แล้วตามด้วย `0002_storage_and_jobs.sql`
   - ถ้าจะให้ระบบปล่อยที่ที่ไม่จ่ายเงินอัตโนมัติ ให้เปิด extension `pg_cron` ก่อนรัน 0002
3. รัน `supabase/migrations/0003_exec_report.sql` (รายงานผู้บริหาร), `0004_booking_code.sql` (รหัสการจองไม่ซ้ำ), `0005_staff_and_admin.sql` (ล็อกอินหลังบ้าน) `0006_drivers.sql` และ `0007_driver_claims.sql` (บัญชีคนขับ)
   แล้วสร้างแอดมินคนแรก: `select staff_create('admin', 'ผู้ดูแลระบบ', 'admin', 'รหัสผ่านยาว-10-ตัวขึ้นไป', null);`
4. ถ้าอยากให้หน้าแอดมินมีข้อมูลตัวอย่าง: รัน `supabase/seed_demo.sql` และถ้าอยากให้รายงานผู้บริหารมีข้อมูลย้อนหลัง 2 ปี รัน `supabase/seed_history.sql` ต่อ (ห้ามรันในฐานข้อมูลจริง)
5. Project Settings › API: คัดลอก Project URL กับ `service_role` key

### 2. LINE
1. สร้าง LINE Official Account (แพ็กเกจฟรี) แล้วเปิดใช้ Messaging API
2. ใน LINE Developers ช่อง Messaging API: คัดลอก Channel secret และออก Channel access token
3. สร้างช่อง LINE Login ใน Provider เดียวกัน แล้วเพิ่ม LIFF app:
   - Size: Full · Endpoint URL: `https://<โดเมน Vercel>/liff` · Scope: `openid`, `profile`
   - คัดลอก LIFF ID และ Channel ID ของช่อง LINE Login
4. หลัง deploy แล้ว: ตั้ง Webhook URL เป็น `https://<โดเมน>/api/line/webhook` และเปิด Use webhook
5. ใน LINE OA Manager › ตั้งค่าการตอบกลับ: เปิดทั้ง Chat และ Webhook (แอดมินยังแชทเองได้)

### 3. Vercel
1. Push โฟลเดอร์นี้ขึ้น GitHub แล้ว Import ใน Vercel
2. ใส่ Environment Variables ตาม `.env.example`
3. Deploy

### 4. เมนู LINE
```bash
cp .env.example .env.local   # ใส่ค่าจริง
npm install
npm run richmenu             # สร้างเมนู 5 ปุ่ม อัปโหลดรูป ตั้งเป็นเมนูหลัก
```

## เดโม 5 นาที
1. ให้ลูกค้าสแกน QR เพิ่มเพื่อน LINE OA จะได้การ์ดต้อนรับ และเห็นเมนู
2. กด "จองที่จอดรถ" แล้วกรอกฟอร์ม จะเห็นว่าที่ว่างและราคาเปลี่ยนทันที
3. จ่ายผ่าน QR (เดโมใช้ `SLIP_PROVIDER=mock` ส่งรูปอะไรก็ผ่าน ถ้าจะตรวจจริงให้เปลี่ยนเป็น `easyslip` หรือ `slipok` แล้วโอนจริง 1 บาท โดยตั้งราคาเดโมให้ต่ำ)
4. ได้ข้อความยืนยันในแชท
5. เข้า `/login` แล้วเปิด `/admin` ให้ดูว่าที่ว่างลดลง มีทะเบียนรอเพิ่มเข้าไม้กั้น และเที่ยวรถถูกจัดให้รถแล้ว
6. ล็อกอินบัญชีคนขับบนมือถืออีกเครื่อง เปิด `/driver` แล้วกดสถานะงาน ลูกค้าจะได้ข้อความใน LINE
7. ผู้บริหารเข้า `/login` ด้วยบัญชีสิทธิ์ผู้บริหาร (แอดมินสร้างให้ที่ `/admin/users`) จะเห็น `/exec` รายงานผู้บริหาร ดูรายได้และลูกค้าแบบรายวัน รายสัปดาห์ รายเดือน รายปี และดาวน์โหลด CSV ได้

## ตรวจสลิปอัตโนมัติ (EasySlip)
ตั้งใน Vercel: `SLIP_PROVIDER=easyslip`, `EASYSLIP_API_KEY=<key>` และ `PROMPTPAY_ID` เป็นพร้อมเพย์จริงของร้าน แล้ว Redeploy

ระบบยืนยันการจองให้อัตโนมัติเมื่อผ่านครบ 4 ข้อ
1. สลิปจริงและไม่เคยถูกใช้ (EasySlip ตรวจกับธนาคาร และตรวจสลิปซ้ำ)
2. โอนเข้าบัญชีร้าน: เทียบตัวเลขที่ธนาคารแสดงในสลิปกับ `PROMPTPAY_ID` / `SHOP_BANK_ACCOUNT` หรือให้ EasySlip เทียบกับบัญชีที่ลงทะเบียนไว้ (`EASYSLIP_MATCH_ACCOUNT=true`)
3. ยอดเงินไม่น้อยกว่ายอดที่ต้องจ่าย
4. โอนหลังเวลาที่จอง (กันการเอาสลิปเก่ามาใช้)

ถ้าสลิปไม่บอกบัญชีผู้รับ ธนาคารกรุงเทพยังไม่ยืนยัน หรือระบบ EasySlip ขัดข้อง: ระบบกันที่ไว้ 1 ชั่วโมง และสลิปจะไปขึ้นในหน้าแอดมินให้กดยืนยันเอง

## หลังบ้าน (`/login`)
- สิทธิ์ **แอดมิน**: ภาพรวม · การจอง (ค้นหา แก้ไข เช็กอิน/เอาต์ ยกเลิก รับเงินเอง เพิ่มวันจอด) · รถรับส่ง (เลือกรถ เปลี่ยนเวลา) · รายงาน · ตั้งค่าราคา/ช่องจอด · ผู้ใช้
- สิทธิ์ **ผู้บริหาร**: ดูรายงานอย่างเดียว
- รหัสผ่านเก็บแบบเข้ารหัส (bcrypt) · ใส่ผิด 5 ครั้งล็อก 15 นาที · ล็อกอินอยู่ได้ 12 ชั่วโมง · ปิดบัญชีแล้วใช้ไม่ได้ทันที
- ทุกการแก้ไขของแอดมินถูกบันทึกในตาราง `admin_audit` และแสดงในหน้าการจองนั้น
- ต้องตั้ง `SESSION_SECRET` ใน Vercel (สุ่มยาว 32+ ตัว) · ไม่ใช้ `ADMIN_PASSWORD` / `EXEC_PASSWORD` แล้ว

## คนขับ (`/driver`)
- แอดมินสร้างบัญชีสิทธิ์ **คนขับ** ที่ `/admin/users` พร้อมเบอร์โทร (แสดงให้ลูกค้า) คนขับไม่ผูกกับรถ เห็นงานทุกคัน
- ใครกดสถานะแรกของงานจะเป็นผู้ดูแลงานนั้น ชื่อและเบอร์ในข้อความถึงลูกค้าเป็นของคนนั้น คนขับอื่นรับงานแทนได้โดยติ๊ก “รับงานแทน”
- ขาไปสนามบิน: พร้อมรับที่ลาน → ออกเดินทาง → ส่งถึงสนามบิน (ข้อความขอบคุณ อวยพรให้เดินทางปลอดภัย และบอกวัน-เวลา-จุดนัดรับวันกลับ)
- ขากลับ: ออกไปรับ → ถึงจุดนัดรับ → ส่งถึงลาน
- แจ้งปัญหา/หมายเหตุ: ขึ้นในหน้าภาพรวมของแอดมินจนกว่าจะกด “รับทราบ” และเลือกส่งให้ลูกค้าได้
- ข้อความถึงลูกค้าเป็นการ์ด LINE สีแบรนด์ แบบ push (นับโควตาข้อความรายเดือนของ OA) ส่งได้เฉพาะลูกค้าที่จองผ่าน LINE คนขับติ๊กไม่ส่งเป็นรายครั้งได้

## รายงานผู้บริหาร (`/exec`)
- รายได้ = สลิปที่ตรวจผ่านแล้ว นับตามวันที่ได้รับเงิน แยกค่าจอด รถรับส่ง และจอดเพิ่ม/เกินวัน
- รถเข้าใช้บริการ = การจองที่ชำระแล้ว นับตามวันที่รถเข้าลาน แยกลูกค้าใหม่ (จองครั้งแรก) กับลูกค้าเดิม
- อัตราการใช้ลาน = วันที่มีรถจอดรวม ÷ (60 ช่อง × จำนวนวัน)
- ช่วงปัจจุบัน (วันนี้/สัปดาห์นี้/เดือนนี้/ปีนี้) นับถึงวันนี้เท่านั้น
- ตัวเลขทั้งหมดคำนวณในฐานข้อมูลด้วยฟังก์ชัน `exec_report(grain, periods)`

## ทดลองในเครื่องโดยไม่ต้องมี LINE
ตั้ง `DEMO_MODE=true` แล้วไม่ต้องใส่ `NEXT_PUBLIC_LIFF_ID` จากนั้น `npm run dev` แล้วเปิด http://localhost:3000
ระบบจะใช้ผู้ใช้สมมติชื่อ `demo-user` (ห้ามเปิด DEMO_MODE ตอนใช้งานจริง)

## สิ่งที่ยังไม่มีในเดโม (ตามแผนเฟส)
- ส่งทะเบียนเข้าไม้กั้นอัตโนมัติ (ตอนนี้แอดมินกด "ทำแล้ว" ตามคิว)
- ติดตามเที่ยวบินอัตโนมัติ (ตอนนี้ลูกค้ากรอกเวลาเครื่องลงเอง)
- การเลื่อนวันจากหน้าลูกค้า (มีฟังก์ชันในฐานข้อมูลแล้ว: `reschedule_booking`)
- ตรวจบัญชีผู้รับในสลิปกับ EasySlip (ต้องลงทะเบียนบัญชีรับเงินในระบบ EasySlip ก่อน)

## ทดสอบแล้ว
- `npm run build` ผ่าน (Next.js 15)
